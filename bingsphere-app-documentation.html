Bingsphere system guide

How the Mini Netflix app works

This document explains the functioning of the Bingsphere streaming platform: the Angular frontend, Django REST backend, API data transmission, JWT authentication, Cloudinary media handling, admin management, and deployment flow.

Project identity
  • Frontend: Angular single page application
  • Backend: Django 6 + Django REST Framework
  • Authentication: JWT access and refresh tokens
  • Media: Cloudinary-backed image uploads
  • Deployment target: Render backend, separate frontend host

01 Overview

Application purpose

Bingsphere is a streaming catalog application inspired by Netflix. Users authenticate, browse curated movie rows, search titles, play embedded videos, manage a personal watchlist, and update profile information.

Catalog browsing

Movies are grouped into curated home collections. The frontend receives featured content, rows, catalog data, and continue-watching progress from the backend.

User accounts

Registration creates a Django user and profile. Login returns JWT tokens, and protected API requests use the access token in the Authorization header.

Media delivery

Movie thumbnails, backdrops, and profile avatars are image fields. The app is configured so new uploads use Cloudinary instead of temporary Render disk.

02 Architecture

High-level system map

The application is split into a frontend browser experience and a backend API service. The frontend never talks directly to the database or Cloudinary; it sends HTTP requests to Django, and Django controls persistence.

1

Browser

Angular renders pages, handles search, stores tokens, and submits user actions.

2

Runtime config

app-config.js provides the deployed API base URL to Angular.

3

Django API

DRF validates requests, checks JWT auth, serializes data, and returns JSON.

4

Database

PostgreSQL stores users, movies, genres, watchlists, collections, and progress.

5

Cloudinary

Image uploads are stored externally and returned as URLs for frontend display.

03 Backend

Django backend responsibilities

The backend lives in Backend/. It owns data structure, API behavior, authentication enforcement, upload storage, and the custom Django admin interface.

Core models

  • Movie: title, description, release date, poster, backdrop, video URL, type, duration, rating, featured rank.
  • Genre: unique genre names attached to movies.
  • HomeCollection: curated home rows such as trending or new releases.
  • HomeCollectionItem: ordered relationship between a collection and a movie.
  • Watchlist: one saved movie per user.
  • WatchProgress: continue-watching progress per user and movie.
  • Profile: one-to-one user profile with avatar image.

Backend services

  • Django REST Framework exposes JSON endpoints.
  • Simple JWT issues access and refresh tokens.
  • Django admin manages catalog, collections, users, profiles, and media previews.
  • WhiteNoise serves collected static files in production.
  • Cloudinary storage handles user and catalog image uploads.
User Owns profile, watchlist entries, and watch progress.
Movie Has genres, images, metadata, and a playable video URL.
Collection Controls the rows displayed on the home screen.
Cloudinary Stores thumbnails, backdrops, and avatars outside the app disk.
04 API

API endpoints and data transmission

The API base URL is normalized by Angular and then used by services such as ApiService and AuthService. Most endpoints require a JWT access token.

Endpoint Method Purpose Auth
/api/health/ GET Render health check endpoint. Returns { "status": "ok" }. Public
/api/register/ POST Creates a Django user and matching profile. Public
/api/token/ POST Validates username and password. Returns JWT access and refresh tokens. Public
/api/token/refresh/ POST Accepts a refresh token and returns a new access token. Public with refresh token
/api/home/ GET Returns featured movie, full catalog, curated rows, and continue-watching data. JWT required
/api/movies/ GET Lists movies and supports search over title and description. JWT required
/api/movies/{id}/ GET Returns one movie for the video player page. JWT required
/api/watchlist/ GET, POST Lists saved movies or adds a movie to the signed-in user's list. JWT required
/api/watchlist/{id}/ DELETE Removes a saved watchlist item. JWT required
/api/profile/ GET, PATCH Loads the current profile, uploads an avatar, or removes an avatar. JWT required
/api/profile/password/ POST Validates current password and saves a new password. JWT required
/api/storage-check/ GET Reports whether the deployed default storage is using Cloudinary. Public diagnostic
05 Frontend

Angular frontend behavior

The frontend is a standalone Angular application. It uses routes for each screen, service classes for HTTP communication, and shared navbar/footer components for navigation.

Routes

/login, /home, /movies, /mylist, /watch/:id, /profile, /privacy-policy, and /terms-of-use.

Services

AuthService handles registration, login, logout, and token storage. ApiService loads movies, home data, watchlist, profile, avatars, and password updates.

Design flow

The home screen uses a cinematic hero, search-enabled navbar, curated content rows, continue-watching cards, poster grids, and feedback toasts.

Runtime API configuration: frontend/public/app-config.js stores API_BASE_URL. Angular reads it through runtime-config.ts, normalizes the URL, and builds endpoint paths with apiUrl(). This prevents deployed frontend code from being locked to localhost.
06 Cloudinary

Media upload and delivery

Render's free filesystem can lose uploaded files after rebuilds or restarts. This project avoids that by configuring Django's default file storage to Cloudinary for media uploads.

How uploads are stored

Movie.thumbnail, Movie.backdrop, and Profile.avatar are Django ImageField fields. Because STORAGES["default"] points to cloudinary_storage.storage.MediaCloudinaryStorage, new image uploads are sent to Cloudinary.

Required environment variables

  • CLOUDINARY_CLOUD_NAME
  • CLOUDINARY_API_KEY
  • CLOUDINARY_API_SECRET
STORAGES = {
  "default": {
    "BACKEND": "cloudinary_storage.storage.MediaCloudinaryStorage",
  },
  "staticfiles": {
    "BACKEND": "whitenoise.storage.CompressedManifestStaticFilesStorage",
  },
}
07 Deployment

Production configuration

The backend is prepared for Render. The frontend can be hosted separately as long as API_BASE_URL points to the deployed backend API.

Backend service

  • Root directory: Backend
  • Build command: bash build.sh
  • Start command: python -m gunicorn backend.wsgi:application --workers 2 --timeout 120
  • Health check: /api/health/

Production settings

  • DATABASE_URL configures PostgreSQL through dj-database-url.
  • RENDER_EXTERNAL_HOSTNAME is added to allowed hosts.
  • CORS_ALLOWED_ORIGINS allows the Angular frontend domain.
  • SECRET_KEY and Cloudinary keys must be set in Render.
Important: render.yaml documents a blueprint-style deployment, but if the service was created manually in Render, the Render dashboard settings are the active source of truth.
08 Request flow

Example: loading the home page

This is the normal path a signed-in user follows when opening the catalog.

Step 1

The user logs in. Django validates credentials through /api/token/ and sends back access and refresh tokens.

Step 2

Angular stores tokens in localStorage. The auth interceptor attaches the access token to protected requests.

Step 3

The home component calls ApiService.getHomePage(), which requests /api/home/.

Step 4

Django builds the response: featured movie, catalog, collections, and continue-watching records for the authenticated user.

Step 5

Serializers convert Django models into JSON and build absolute media URLs for thumbnails, backdrops, and avatars.

Step 6

Angular renders the hero, rows, search state, poster cards, continue-watching cards, and playback navigation.

10 Summary

Core functionality in one paragraph

Bingsphere works by letting Angular present a streaming interface while Django controls trusted operations. The browser sends requests through typed services; JWT tokens prove the user's identity; DRF views query and serialize database models; Cloudinary stores and serves uploaded media; and the frontend turns the returned JSON into a polished catalog, watchlist, profile, and video playback experience.
